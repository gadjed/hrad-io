# План виправлення навчання планувальника

Статус: **план, без реалізації.** Відповіді зафіксовано 2026-09-19.

---

## 0. Короткий підсумок першого прогону

| Лічильник | Значення | Що це |
|-----------|----------|--------|
| `--timesteps` | 1 000 000 | gym-кроки = рішення мережі |
| PPO `n_steps` | **256** | кроків на **одне оновлення ваг** (не інтервал Ollama) |
| Ітерації на дашборді | ≈ 3907 | `1_000_000 / 256` |
| `--ollama-freq` | 10 | Ollama раз на **10 gym-кроків**, не на 256 |

256 на дашборді / у прогрес-барі — це довжина rollout PPO. Перевірки Ollama йшли частіше (кожні 10 кроків), якщо крок не був `wait`.

**Що вивчила мережа:** продати стартовий прототип → refund 60% → спам лісопилок. Причини: старт уже збудований; `sell` багатить; utility платить за mill coverage; **місце** обирав parameterizer, не мережа.

## 1. Зафіксовані рішення

| # | Питання | Рішення |
|---|---------|---------|
| Q1 | Що таке 1кк | **Gym-кроки** (як зараз `--timesteps`). PPO-ітерації й Ollama-виклики показувати окремо. |
| Q2 | Правильно / ні | **score > 7.0** (70% від 0–10) ⇒ `ok=true`. |
| Q3 | Що тренуємо зараз | **Лише планувальник розбудови.** Бот-юніт і грінд — не в цьому тренуванні. |
| Q4 | Що є в env | **Немає** монстрів, бота, дерев, руд. Порожній keep + цитадель. Лише «який наступний крок бази». |
| Q5 | Рівні моделей | **Спочатку тільки L1.** L2+ не стартувати, поки L1 не ок за вашою оцінкою. |
| Q6 | Захист | Див. §3. Не «стіна поруч», а **замкнений контур** + вежі. |
| Q7 | Дія мережі | Одна модель, **дві голови** (пояснення нижче). Не дві мережі. |
| Q8 | 3 помилки | **Підряд** `ok=false` → скид до самої цитаделі. Щоб не перенатренувати на `sell`. |
| Q9 | Refund продажу | **Як у коді гри** (зараз 60%). У RL гроші ∞, тож sell не для заробітку. |
| Q10 | Калібрація Ollama на фортах | **Пауза.** Під час навчання ви самі дивитесь, чи Ollama не бреше. |
| Q11 | Бій / бот-юніт | **Потім.** Логіка юніта — звичайний алгоритм, без моделі. |

Curriculum відкриття (`mill → quarry → goldmine → tower → walls`) лишається **фазою тієї ж L1-моделі**, цитадель уже стоїть.

## 2. Що таке «дві голови» (Q7)

Це **не** дві нейромережі і **не** два тренування.

Зараз крок виглядає так:

```
мережа → одне число 0..19  («постав mill»)
код     → сама шукає tx,ty
```

Мережа не винна, *куди* стала лісопилка. Тому overlap і «дірка в стіні» вона не вчиться.

**Дві голови** = один zip, один optimizer, один gym-крок, два виходи одночасно:

```
спільний encoder сітки keep
    ├─ голова A: що робити  (place mill / upgrade tower / sell / wait / …)
    └─ голова B: яка клітинка keep
```

Нагорода одна на обидва виходи. Якщо mill поставили вперехрест з іншою — штраф бачить і «що», і «куди».

Інші варіанти, які **не** беремо зараз:

- Одна гігантська дія `тип × клітинка` (тисячі кнопок, важка маска).
- Два gym-кроки підряд («спочатку тип, потім клітинка») — плутає, що саме хвалила Ollama.

У грі parameterizer може лишитись запасним, поки ONNX не вміє клітинку. У **gym для навчання** магічний `findHarvestSite` як єдине джерело координат вимикаємо.

## 3. Захищеність (заміна «стіна з усіх сторін»)

Для кожної цінної споруди (harvest, core, вежі; вага × рівень):

| Стан | Оцінка |
|------|--------|
| Є шлях ззовні keep до будівлі (контур не замкнений, навіть якщо стін багато) | **не захист** |
| Один замкнений контур стін/брам **і** є вежа, що прикриває цей контур | захист |
| Два вкладені замкнені контури **і** вежі | сильний захист |
| Замкнені стіни, але **немає веж** | **не захист** |

«Кілька стін з вільним проходом» ≠ контур. Дорожча / вищого рівня будівля без контуру — більший штраф.

У design-env **немає** дерев і руд, тому overlap видобутку рахуємо **геометрією радіусів** однотипних mill/quarry/goldmine, не спільними вузлами карти.

## 4. Цільовий training env (L1)

```
старт:        keep L1, лише core, без прототипу, без світу з нодами
гроші:        ∞ (canAfford завжди, фокус на черзі розбудови)
немає:        монстри, боти, дерева, руди
крок:         (op, type, cell) → миттєвий place/upgrade/sell
нагорода:     захист-контуром + вежі + анти-overlap harvest
              + 0.3·Ollama, ok ⇔ score > 7
скид:         3 підряд not-ok → знову лише core
модель:       models/rl_agent/L1/
Ollama:       як зараз за частотою; на дашборді окремий лічильник викликів
```

Гравець у звичайній грі не змінюється цим env. Скрипт бота-юніта — окремий пізніший зріз, без RL.

## 5. Фази (оновлений порядок)

Фазу ігрового бота знято з критичного шляху. Калібраційний скрипт Ollama на паузі.

### Фаза 0 — Чесні лічильники + resume

- Дашборд окремо: gym steps, PPO updates, Ollama evals.
- Не підписувати PPO-ітерацію як «спробу навчання».
- `--resume` з останнього чекпоінта, щоб Стоп не починав з нуля.

Файли: `scripts/train-rl-ollama.py`, `shared/train-dashboard-state.mjs`, `public/train/dashboard.js`.

### Фаза 1 — Design-env без світу-шуму

- Не штампувати прототипи.
- Не спавнити ноди / монстрів / ботів.
- Старт: core L1 у порожньому keep.
- `SETTLEMENT_GYM_INFINITE_TREASURY=1`.
- `sellValue` **не чіпати** (як у грі). У цьому env sell не наливає сенсу, бо казна і так повна; лишається звільнення клітинки.

Файли: `scripts/settlement-gym-worker.mjs`, `server/World.mjs` (режим empty keep) або окремий builder env.

### Фаза 2 — Reward розкладки

- Контурний захист + вимога веж (§3).
- Штраф перетину радіусів однотипного видобутку; бонус за рознесені зони.
- Штраф суцільного забиття keep стінами/вежами без проходів (місця під майбутні ноди в грі).
- Вага захисту × рівень будівлі.

Файли: `server/SettlementPlanner.mjs`, промпт Ollama (ті самі правила текстом).

### Фаза 3 — Дві голови, сітка L1

- Observation: фіксована сітка keep L1 (тип, рівень, чи в замкненому контурі, overlap-маска радіусів).
- Action: голова A = op/type, голова B = клітинка; маска нелегального.
- Parameterizer у gym не вибирає місце сам.
- Один чекпоінт `L1`. L2 не починати.

Файли: `server/SettlementPlanner.mjs`, `scripts/train-rl-ollama.py`, нова політика/shape obs.

### Фаза 4 — Ollama як вчитель + анти-sell

- `ok = score > 7`.
- 3 підряд `ok=false` → reset до core (не кінець training).
- Локальне правило: 3 `sell` підряд без `place` = fail навіть до Ollama (щоб не зависати на знесенні).
- Wait як і раніше можна дешево пропускати по симуляції.

Файли: worker, `OllamaEvaluator.mjs`.

### Фаза 5 — Curriculum відкриття (та ж L1, без другої моделі)

- На старті епізоду експерт підказує чергу: mill → quarry → goldmine → tower → кільце стін (місця — без overlap, з думкою про майбутній контур).
- Короткий imitation / маска «нелегальних на цьому етапі» типів.
- Потім маску зняти, лишити Ollama.

Цитадель завжди вже є; мережа вчить **другу** будівлю і далі.

### Фаза 6 — Дашборд якості

- Кругова: last 100 Ollama, два кольори (`score > 7` / ні).
- Хронологія вердиктів по осі кроків.
- KPI: `ok_rate_100`, `fail_streak`, `resets_to_core`.
- Ви під час прогону дивитесь картки «поточний / попередній» і ловите брехню Ollama вручну (замість фази калібрації на прототипах).

### Фаза 7 — Пізніше, не цей зріз

- L2+ моделі.
- Бот-юніт алгоритмом (черга, фарм, combat interrupt).
- Монстри в env.
- Автокалібрація Ollama на ручних фортах.
- ONNX планувальника в живій грі.

## 7. Порядок робіт

1. Фаза 0 — лічильники, resume.  
2. Фаза 1 — порожній L1 keep, ∞ грошей, без нод/мобів/бота.  
3. Фаза 2 — контур, вежі, overlap.  
4. Фаза 3 — дві голови на сітці.  
5. Фаза 5 — коротка черга відкриття, потім Фаза 4 (Ollama + скид).  
6. Фаза 6 — діаграми на дашборді.  
7. Довгий прогін L1. L2 і бот-юніт — після вашого «L1 справляється».
